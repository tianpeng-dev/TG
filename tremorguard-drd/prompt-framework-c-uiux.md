# Prompt：TremorGuard 方案 C — 对话式交互 UI/UX 生成

> 本 Prompt 可直接复制粘贴至 Figma AI、v0.dev、Claude Artifacts 或任何支持 UI 生成的 AI 工具，用于生成 TremorGuard 帕金森震颤监测 App 的高保真 UI 设计。

---

## 1. 角色与目标

你是一名专注医疗健康领域的资深 UI/UX 设计师。你的任务是为一款面向帕金森患者的可穿戴设备配套 App 生成完整的移动端 UI 设计。

**核心目标**：让 50–85 岁的帕金森患者（存在震颤和认知障碍）能够零学习成本地使用应用，所有信息以对话形式主动推送给用户，用户只需点击大按钮完成操作。

---

## 2. 产品背景

**产品名称**：TremorGuard
**产品定位**：帕金森患者震颤监测腕带的配套移动应用
**核心功能**：
- 腕带通过 BLE 5.0 实时采集震颤数据（50Hz 采样，4-12Hz 带通滤波）
- 自动生成每日/每周临床报告
- 用药提醒与记录
- 异常事件检测与警报
- 报告分享给医生（支持 A4 打印）

**技术栈**：React Native（iOS + Android 双平台）

---

## 3. 目标用户画像

- **年龄**：50–85 岁
- **病症**：帕金森病，存在静止性震颤、运动迟缓、肌强直
- **认知特征**：工作记忆下降、执行功能减退、注意力维持困难、对延迟极度敏感
- **使用场景**：单手操作、可能在震颤发作时使用、视力可能退化
- **设计基准**：以最差能力状态为设计基准，而非平均水平

## 5. 核心交互范式：对话式消息流

**核心隐喻**："口袋里的贴心护士"

**首页就是一个消息流**，类似与护士的微信聊天界面。系统主动发送消息，用户通过点击大按钮应答。交互从"用户找功能"变为"功能找用户"。

### 5.1 页面整体结构

```
┌─────────────────────────────┐
│  状态栏（时间、信号、电量）       │
├─────────────────────────────┤
│  [设备图标]  TremorGuard   [设置] │  ← 顶部导航栏，高度 56dp
├─────────────────────────────┤
│                             │
│  ┌─────────────────────┐    │
│  │ 🤖 早安，张阿姨        │    │  ← 系统头像 + 系统消息气泡
│  │ 昨晚睡眠期间震颤 2 次   │    │
│  │ 每次约 15 分钟        │    │
│  │ [知道了] [查看详情]    │    │  ← 大按钮，60dp 高
│  └─────────────────────┘    │
│                             │
│  ┌─────────────────────┐    │
│  │ ⚠️ 12:00 该服用左旋多巴 │    │  ← 用药提醒消息（琥珀色边框）
│  │ 250mg 了            │    │
│  │ [✓ 已服药] [稍后提醒]  │    │
│  └─────────────────────┘    │
│                             │
│  ┌─────────────────────┐    │
│  │ 📊 今日报告已生成      │    │  ← 日报告消息
│  │ 本周震颤强度下降 18%   │    │
│  │ [查看完整报告]         │    │
│  └─────────────────────┘    │
│                             │
│           ...               │
│                             │
├─────────────────────────────┤
│  [首页]  [报告]  [我的]      │  ← 底部 Tab 导航，高度 64dp
└─────────────────────────────┘
```

### 5.2 顶部导航栏（56dp 高）

- **左侧**：设备连接状态图标（绿色圆点 = 已连接，灰色 = 未连接），点击跳转设备管理
- **中间**：产品名称 "TremorGuard"，18sp，中等字重
- **右侧**：设置齿轮图标（48dp 触控区域），点击跳转设置页

### 5.3 底部 Tab 导航（64dp 高）

三个 Tab，图标 + 文字标签：
- **首页**（消息流）— 当前选中态：深青色图标 + 文字
- **报告**（报告列表）— 默认态：灰色图标 + 文字
- **我的**（个人中心）— 默认态：灰色图标 + 文字

每个 Tab 触控区域 ≥ 48dp × 64dp，图标 24dp，文字 12sp。

## 6. 消息卡片类型详解

每条消息是一个圆角卡片（16px），系统消息左侧带一个小机器人/护士头像（32dp 圆形）。卡片内包含消息内容 + 1-2 个大按钮（60dp 高，全宽或并排）。

### 6.1 晨间摘要消息

**出现时机**：每天上午 8:00 自动推送
**卡片样式**：浅青色背景（`#F0FDFA`），左侧深青色竖条装饰（4px 宽）
**内容结构**：
```
🤖 早安，昨日整体状况良好

睡眠期间震颤 2 次，每次约 15 分钟
晨起服药后 30 分钟起效

[知道了]      [查看详情]
```
**按钮**：
- 「知道了」— 深青色背景，白色文字，20sp 粗体，60dp 高，圆角 12px
- 「查看详情」— 白色背景，深青色边框 2px，深青色文字，同上尺寸

**点击「知道了」后**：按钮变为禁用态（灰色背景 + 勾图标），卡片底部追加一行小字："已确认 08:05"

### 6.2 用药提醒消息

**出现时机**：根据用药计划时间推送
**卡片样式**：浅琥珀色背景（`#FFFBEB`），左侧琥珀色竖条装饰（4px 宽），顶部带小药丸图标
**内容结构**：
```
💊 12:00 用药提醒

该服用左旋多巴 250mg 了
预计 45 分钟后药效达峰

[✓ 已服药]    [稍后提醒]
```
**按钮**：
- 「✓ 已服药」— 绿色背景（`#059669`），白色文字
- 「稍后提醒」— 灰色背景（`#E5E7EB`），深灰文字

**点击「已服药」后**：整个卡片背景淡化为浅绿色，显示 "✓ 已记录 12:03"，系统回复一条新消息："已记录。预计 12:45 药效达峰，届时若震颤未缓解将提醒你。"

**点击「稍后提醒」后**：卡片状态不变，15 分钟后推送新的用药提醒消息。

### 6.3 异常警报消息（置顶）

**出现时机**：检测到震颤阈值超标或剂末现象
**卡片样式**：浅琥珀色背景，边框 2px 琥珀色，顶部带红色圆点脉冲动画（表示紧急）
**内容结构**：
```
🔴 异常警报

震颤水平升高（振幅 3.5cm）
检测到剂末现象，建议立即服药

[已服药]  [通知照护者]  [查看数据]
```
**按钮**：三个按钮横向排列，每个约占 1/3 宽度，间距 12px

**特殊行为**：
- 该消息始终置顶，新消息出现在其下方
- 10 分钟内无用户响应，自动发送照护者通知，并在消息流中追加一条系统消息："已通知女儿张琳，她正在查看你的数据"
- 用户响应后，红色脉冲消失，卡片边框变灰

### 6.4 日报告消息

**出现时机**：每日 21:00 自动生成后推送
**卡片样式**：白色背景，左侧深青色竖条
**内容结构**：
```
📊 今日报告已生成

本周震颤强度下降 18%
日均发作次数：3.2 次 → 2.1 次

[查看完整报告]  [分享给医生]
```
**点击「查看完整报告」后**：卡片内联展开（高度动画过渡），在卡片内部展示：
- 一句话结论（大字 20sp，深青色）
- 3 个关键指标数字（大数字 + 小标签，横向排列）
- 简版趋势图（折线图，高度 120px，7 天数据）
- 「展开更多」按钮，点击后跳转全屏报告页

**点击「分享给医生」后**：底部弹出操作面板（Action Sheet）：
- 通过短信发送链接
- 通过邮件发送 PDF
- A4 打印
- 取消

### 6.5 系统确认/反馈消息

**样式**：无头像，居中对齐的灰色小字气泡，背景透明
**示例**："已记录。预计 45 分钟后药效达峰。" 或 "已通知女儿张琳。"
**字号**：14sp，灰色（`#6B7280`）

## 8. 关键交互规范（不可妥协）

| 规范 | 要求 |
|------|------|
| 最小触控目标 | 常规元素 48dp × 48dp；关键按钮 60dp × 60dp |
| 按钮间距 | 相邻可点击元素间距 ≥ 16dp，防止震颤误触 |
| 手势禁令 | **禁止**捏合缩放、长按唤起、滑动删除、拖拽排序。所有操作通过单击完成 |
| 反馈即时性 | 所有操作须在 100ms 内给出视觉反馈（按压态、颜色变化） |
| 单页单任务 | 每个页面承载且仅承载一个主要任务 |
| 离线可用 | 所有核心功能无需网络即可使用 |
| 文字可读性 | 正文最小 18sp，年级水平 ≤ 6（Flesch-Kincaid） |
| 对比度 | 文字与背景 ≥ 7:1 |
| 加载状态 | 网络请求超过 1 秒须显示进度指示器，禁止空白等待 |

## 9. 动画与过渡

- **消息进入**：新消息从底部滑入（translateY 20px → 0，opacity 0 → 1，duration 300ms，ease-out）
- **卡片展开**：高度动画（height auto 过渡，duration 400ms，ease-in-out）
- **按钮按压**：scale 0.97，duration 100ms
- **状态变化**：颜色过渡（background-color 过渡，duration 200ms）
- **禁止**：复杂动画、视差滚动、闪烁元素（可能诱发帕金森患者焦虑）
